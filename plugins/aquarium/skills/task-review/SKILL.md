# Task Review

Read [review-routing-contract.md](../../references/review-routing-contract.md) for route selection, evidence combinations, recovery, and assessment ordinals. Read [review-intent-contract.md](../../references/review-intent-contract.md) for the shared Review Brief and criterion-level completion assessment. Always read [evidence-residency.md](../../references/evidence-residency.md) and [finding-disposition.md](../../references/finding-disposition.md).

Review only the Task established by `/aquarium:task-handler`. Require its exact objective, criteria and authorities; base revision; candidate identity; ordered work commits when present; included implementation, tests, refinement and review-state documentation; excluded state; verification evidence; selected route; positive assessment ordinal when the checkpoint completes; current goal revision; assessment kind; and review mode. Ordinals one through three use `work-unit`; ordinal four and later use `remediation-confirmation`. A direct invocation is one isolated report-only `work-unit` checkpoint with ordinal one and grants no remediation or later-checkpoint budget.

A completed delegated review or completed waiver assessment consumes one ordinal even when it reports findings or a failing Mulgae backend check. An incomplete or failed operation consumes no ordinal. Native recovery inside one operation does not consume another ordinal. A route switch after a completed checkpoint uses the next ordinal and preserves the earlier result; a switch after an incomplete operation retains the current ordinal.

Corrections returned to an owning phase change the target and invalidate affected prior evidence, including implementation and verification evidence when behavior or tests change. Record native finding counts as descriptive source facts and derive separate phase-owned obligation totals from backend-check remediation, valid findings, and unmet completion criteria. Admit operation, finding confirmation, backend check, completion, finding class, rework authority, and implementation, verification, or documentation ownership through separate serial decisions. Only an admitted completed or waived operation, a passing or legitimately absent backend check, a `complete` completion state, a clean finding class, and no file change support Task approval.

## Dispatch the Selected Route

1. Verify that the route in the approved Task envelope is exactly one of `mulgae`, `orca`, `native-codex`, or `waived`. Check only that route's prerequisites. Do not fall back to another route or create a stored preference.
2. Select one target containing the complete Task diff and excluding unrelated work. Stop when safe isolation cannot be established. Orca may use `staged` only when the complete Task candidate is isolated from unrelated index entries; do not alter the index to manufacture eligibility.
3. Build one Review Brief naming the Task, actual requirement set, checkpoint, base revision, exact target, ordered work or correction commits when present, included and excluded paths and artifacts, verification provenance, goal revision, assessment ordinal, assessment kind, and review mode. A `remediation-confirmation` brief also freezes the earlier finding IDs, prior target, correction delta, invalidated criteria, direct callers, contracts and tests. Use the same brief for route preflight and execution.
4. Dispatch exactly one selected route:
   - For `mulgae`, read [mulgae-review-contract.md](../../references/mulgae-review-contract.md), establish the independent reason, remaining round, target, and original-root lineage, then require the executing agent to load and follow the installed same-release `/use-mulgae` skill before native preflight or execution. That skill owns execution, waiting, and authorized exact recovery. Resume the same invocation when pending.
   - For `orca`, invoke `/aquarium:orca-review` through its approved handler-delegation path with the exact isolated `staged` target and explicit reviewer. Preserve Orca Run, Task, Dispatch, worker, Delivery, acknowledgement, settlement, and recovery evidence without describing it as Mulgae evidence.
   - For `native-codex`, dispatch fresh read-only Grok reviewer subagents through `spawn_subagent` with `background: true`, `isolation: none`, and `cwd` set to the exact Git root, preferring `aquarium:independent-reviewer` and falling back to `explore`, then collect each result with `get_command_or_subagent_output`, with the exact bounded target, complete Review Brief, and static report-only instructions. Require no edits, tests, nested agents, or lifecycle mutation. Preserve the host delegation identity and reviewer provenance without calling it independent review.
   - For `waived`, launch no reviewer. Confirm explicit waiver authority, then have the coordinator assess the complete Review Brief against the exact target and current authorized evidence. Record `review waived`, `assessment-provenance=coordinator-waiver`, and the waiver's reason and assurance limitation.
5. Consume the authoritative result. Aggregate every accepted reviewer report, or the coordinator waiver assessment, into one conservative criterion-level completion assessment. Keep that assessment separate from operation state, backend check, extraction quality, and local finding dispositions.
6. Treat every finding as an advisory hypothesis. Preserve its reported severity, verify it against the roadmap, current code, and tests, assign its effective priority, and select the shared disposition. Preserve earlier findings through route changes.
7. Adjudicate every in-scope finding but do not change files. A `work-unit` assessment may report defects in the named Task objective and candidate, but not unrelated pre-existing issues. A `remediation-confirmation` may report an earlier finding as resolved or unresolved and may add only a correction-caused or directly reachable regression; route unrelated observations to the future-work owner without widening the checkpoint. In delegated `remediation-eligible` mode, return valid findings through the owning phase with required checks and next-checkpoint status. A direct invocation reports findings and the exact `/aquarium:task-handler` continuation without mutation. In `confirmation-only` mode, return Medium-or-higher findings for bounded user authorization and return eligible Low handling to the approved owning envelope without granting another review.
8. On an incomplete or failed operation, return the exact route evidence and stop for one explicit `resume-current`, `switch-route`, `waive`, or `stop` direction. Do not launch another route. Active or uncertain native work must reach an authoritative safe state through its owner before a switch or waiver can be admitted.

## Bound the Evidence

Return the route-neutral fields required by the shared routing contract: `review-route`, `assessment-ordinal` when consumed, `assessment-kind`, `review-operation`, `review-evidence-reference`, `backend-check-result`, `assessment-provenance`, and `waiver-summary` when applicable. Return the exact target, goal revision, review mode, Review Brief identity, bounded route preflight and operation summary, completion-assessment summary and counts, adjudicated findings, whether review predates corrected bytes, missing authority, and remaining operational gaps.

For Mulgae, also return the exact root or verified composite, command exit codes, publication and findings-query state, and native CI decision required by its contract. Keep raw transcripts, accepted reports, extraction artifacts, and credential-profile paths in private Mulgae runtime state. For Orca, preserve its native lifecycle and acknowledgement references. For native Grok, preserve the host delegation reference and reviewer provenance. For a waiver, preserve the explicit authority, target, reason, and assurance limitation without inventing backend evidence.

Task approval separately requires no unresolved Medium-or-higher or confirmation-needed finding, a completed verified disposition for every frozen eligible Low finding, and a completion assessment with zero `unmet` and zero `unverified` criteria. Mulgae additionally requires a passing CI decision. Orca, native Grok, and waiver use `backend-check-result=not-provided`; absence of a backend check does not replace workflow verification. Zero findings, reviewer success, or process exit cannot substitute for semantic completion.

Do not count a cancelled lane, failed or incomplete operation, incomplete capture, unavailable required evidence, or unverified finding as successful review evidence. Do not commit or publish in this phase. Ordinary Low disposition is available for every route. Promoted hardening evidence is Mulgae-only; all other routes report that no promoted hardening evidence applies.

Bound the orchestrator handoff to counts by reported severity, effective priority, validity, and disposition plus at most 20 highest-priority records containing only finding ID, reported severity, effective priority, validity, disposition, and affected repository-relative paths. Bound the separate completion assessment to criterion identity and source, assessment state, remaining gap, and reviewer or coordinator provenance. When more remain, include the omitted count and the authoritative route evidence reference. Never include descriptions, quotes, credential-profile paths, raw provider payloads, subagent transcripts, model names, or runtime identities in tracked repository documentation.
